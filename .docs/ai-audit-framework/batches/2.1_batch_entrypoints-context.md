# Stage 2 — Batch Audit Report: [entrypoints-context]

## Metadata
- **Batch Step ID**: 2.1
- **Profile**: Architecture
- **Scope**: `.tools/browser-automation/execution-context/*`, `index.ts`, `run-smoke.ts`, `run-admin-nav.ts`, `run.ts`, `smoke-automation.ts`

## Strengths
- **Strategy & Template Method Patterns**: Clear abstraction using `ExecutionContext` interface and `BaseExecutionContext` template method for lifecycle setup.
- **Dynamic Context Resolution**: `resolveExecutionContext` supports both registered string keys (`'admin'`, `'guest'`) and pre-instantiated custom context classes.
- **Structured Error Handling**: Context execution traps setup errors cleanly and emits diagnostic events before closing browser instances.

## Findings

### [FINDING-001]: Direct Hardcoded Credential Fallbacks and Weak Auth Config Typing
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/run-smoke.ts#L93-L98`, `.tools/browser-automation/execution-context/AdminContext.ts#L26-L43`
- **Evidence**:
  ```ts
  // run-smoke.ts
  username: process.env.SMOKE_ADMIN_USERNAME || 'admin@pigment-shop.com',
  password: process.env.SMOKE_ADMIN_PASSWORD || 'admin123456',
  
  // AdminContext.ts
  private async fillAndSubmitLoginForm(page: Page, authConfig: any): Promise<void>
  ```
- **Observation**: Default plaintext admin credentials are hardcoded into script fallbacks. `AdminContext` uses untyped `authConfig: any`, bypassing TypeScript compiler guarantees.
- **Impact**: Security vulnerability with exposed credentials; fragile refactoring surface for authentication DOM selectors.

### [FINDING-002]: Duplicate Manual Inspector Injection Lifecycle Hooks
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/execution-context/BaseExecutionContext.ts#L10`, `.tools/browser-automation/index.ts#L54`
- **Evidence**:
  ```ts
  // BaseExecutionContext.ts
  await setupManualInspector(page);
  
  // index.ts (runUIExplorer)
  await setupManualInspector(activePage);
  ```
- **Observation**: `setupManualInspector` is invoked twice in sequence during context execution flow.
- **Impact**: Redundant DOM script injections, memory footprint increase, and potential event handler duplication on Playwright `Page`.

### [FINDING-003]: OS Subprocess Management Mixed into Automation Entrypoint
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/run-smoke.ts#L20-L56`
- **Evidence**:
  ```ts
  if (process.platform === 'win32') {
    const devProc = spawn('cmd.exe', ['/c', 'start', 'cmd', '/k', 'npm run dev'], ...);
  }
  ```
- **Observation**: Entrypoint script directly orchestrates OS child processes, spawning detached command prompt windows to ensure the dev server is active.
- **Impact**: Violates Single Responsibility Principle. Environment bootstrap logic is mixed with test execution lifecycle, making headless CI environment execution unpredictable.

### [FINDING-004]: Fragile Promise Race & Unhandled Hanger in Authentication Verification
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/execution-context/AdminContext.ts#L46-L67`
- **Evidence**:
  ```ts
  const result = await Promise.race([
    authSuccessPromise,
    authErrorPromise.then(res => res ? res : new Promise<any>(() => { }))
  ]);
  ```
- **Observation**: `waitForAuthCompletion` uses `new Promise(() => {})` inside `Promise.race` to swallow empty promise branches indefinitely.
- **Impact**: Memory leak of unhandled pending promises; prone to subtle deadlock states if authentication responses stall.
