## Metadata
- **Batch Step ID**: 2.1

## Strengths

## Findings

### [FINDING-001]: Raw `TouchableOpacity` Sprawl & Primitive Fragmentation
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `src/features/shell/AppHeader/UserDropdown.js#L91-L133`, `src/features/shell/NavMenu/NavMenuHeader.js#L17-L37`, `src/features/shell/NavMenu/LanguageSelector.js#L91-L136`, `src/features/shell/AppHeader/AppHeaderNavLinks.js#L22-L38`
- **Evidence**:
  ```js
  // UserDropdown.js
  <TouchableOpacity style={StyleSheet.flatten([styles.dropdownItem, { flexDirection: 'row', alignItems: 'center' }])} onPress={onToggleUserMenu}>
  </TouchableOpacity>

  // NavMenuHeader.js
  <TouchableOpacity onPress={onBackClick} style={styles.headerLeftBtn} activeOpacity={0.7}>
  </TouchableOpacity>
  ```
- **Observation**: Multiple shell, dropdown, navigation, and menu components directly instantiate raw React Native `TouchableOpacity` instead of wrapping standard `<Button>`, `<IconButton>`, or shared tokenized touchable primitives.
- **Impact**: Inconsistent press visual feedback across the storefront and admin (mixed `activeOpacity` values from 0.7 to 0.8), missing web hover/active micro-animations, and un-unified touch states.

### [FINDING-002]: Inconsistent Press Micro-Interactions (`Button` vs `AnimatedButton`)
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/components/Button.js#L41`, `src/components/ProductPage/ProductReviewSubcomponents.js#L76`, `src/components/ProductPage/ProductImagePanel.js#L89`
- **Evidence**:
  ```js
  // Button.js defaults animated to false:
  export default function Button({ animated = false, ...props }) {
    const Component = animated ? AnimatedButton : TouchableOpacity;
  }
  ```
- **Observation**: Press animations are split between scale spring micro-interactions (`AnimatedButton`) and basic opacity fading (`TouchableOpacity`).
- **Impact**: Creates fragmented visual feel when clicking storefront buttons vs product page actions. Modern design standards require consistent GPU-accelerated spring scale animations for all interactive controls.

### [FINDING-003]: Non-Standardized Touch Target Sizing (< 44x44px)
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/components/SearchToolbar.js#L7-L15`, `src/features/shell/AppHeader/AppHeaderNavLinks.js#L22-L38`
- **Evidence**:
  ```js
  // SearchToolbar.js ClearButton missing hitSlop or minimum 44px bounds:
  function ClearButton({ onClear, value, iconColor }) {
    return (
      <TouchableOpacity onPress={onClear} style={styles.clearBtn}>
        <Ionicons name="close-circle" size={18} color={iconColor} />
      </TouchableOpacity>
    );
  }
  ```
- **Observation**: Small clickable icon buttons and header navigation triggers lack explicit minimum touch target sizing (44x44px) or tokenized `hitSlop` bounds.
- **Impact**: Violates mobile accessibility guidelines and leads to mis-clicks on touch screens.

### [FINDING-004]: Ad-hoc Color Token Bypass in Button Resolvers
- **Severity**: Low
- **Confidence**: High
- **Affected Scope**: `src/components/IconButton.js#L70-L75`, `src/components/ChipButton.js#L10-L15`
- **Evidence**:
  ```js
  // ChipButton.js
  return isDark ? buttonColors.chipDarkInactiveText : buttonColors.chipLightInactiveText;
  ```
- **Observation**: Helper files retain custom color keys (`chipDarkInactiveText`, `glassLightBg`) rather than dereferencing global design tokens (`colors.*`).
- **Impact**: Complicates theme maintenance and risks color leakage during theme updates.
