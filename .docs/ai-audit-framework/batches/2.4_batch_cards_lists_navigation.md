# Stage 2 — Batch Audit Report: Cards, Lists & Navigation

## Metadata
- **Batch Step ID**: 2.4
- **Profile**: Full UI Audit
- **Scope**: `src/components/**`, `app/**` (Product Cards, Category Cards, Lists, Navbars, Headers, Grid Layouts)

## Strengths
- `BaseCard.js` provides structured theme token application for card elevation and backgrounds.
- `useGridLayout.js` standardizes multi-column responsive grid calculation across device viewports.
- `breadcrumbResolver.js` centralizes route-to-breadcrumb transformations for deep navigation.

## Findings

### [FINDING-013]: Bespoke Card Containers & BaseCard Bypass
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `src/components/ProductCard.js#L50`, `src/features/profile/ProfileFormCard.js#L20`, `src/components/Admin/Products/ProductsManager.js#L40`
- **Evidence**:
  ```js
  // ProductCard.js bypasses BaseCard:
  <View style={[styles.card, isDark ? styles.cardDark : styles.cardLight]}>
  // ProfileFormCard.js uses inline cardSpecific overrides:
  backgroundColor: colors.productCardDark
  ```
- **Observation**: Key cards (ProductCard, CategoryCard, ProfileFormCard, Admin items) instantiate custom `View` containers with bespoke radii, borders, and shadows instead of inheriting `<BaseCard>`.
- **Impact**: Inconsistent card border radii (8px vs 12px vs 16px) and surface background elevation tokens across pages.

### [FINDING-014]: Disparate Empty States & Missing Skeleton Loaders
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/components/CartView/CartItemList.js`, `src/features/catalog/CatalogPage.js`, `src/components/Admin/Users/UsersManager.js`
- **Evidence**:
  ```js
  // Cart empty state:
  <Text style={styles.emptyText}>Cart is empty</Text>
  // Admin table empty state:
  <Text style={styles.noData}>No items found</Text>
  ```
- **Observation**: Zero-data and list loading states use unstructured `<Text>` elements or raw `ActivityIndicator` spinners rather than a unified `<EmptyState>` component or `<SkeletonLoader>`.
- **Impact**: Sudden visual pops during data fetching and plain unstyled empty list views.

### [FINDING-015]: Hardcoded Fixed Pixel Card Dimensions in Grids
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/hooks/useGridLayout.js#L12-L17`, `src/utils/layout.js#L16-L25`
- **Evidence**:
  ```js
  // Fixed pixel maps in useGridLayout:
  return { cols: 5, cardWidth: 250, cardMargin: 8 };
  return { cols: 3, cardWidth: 220, cardMargin: 8 };
  ```
- **Observation**: Catalog card grids rely on hardcoded pixel width calculations (`250px`, `220px`) rather than fluid percentage/flex layout containers.
- **Impact**: Causes unwanted horizontal spacing whitespace or slight horizontal overflow on non-standard screen dimensions.

### [FINDING-016]: Fragmented Header & Breadcrumb Layouts across Storefront and Admin
- **Severity**: Low
- **Confidence**: High
- **Affected Scope**: `src/components/PageNavigation.js#L40`, `src/components/Admin/AdminHeader.js`
- **Evidence**:
  ```js
  // PageNavigation displays store breadcrumbs, admin uses custom sub-headers
  ```
- **Observation**: Storefront headers consume `PageNavigation.js`, whereas Admin screens render standalone custom text headers with inconsistent padding and back buttons.
- **Impact**: Mismatched navigation bar aesthetics between Storefront and Admin management modules.
