# Stage 2 — Batch Audit Report: [routing-shell]

## Metadata
- **Batch Step ID**: 2.1
- **Profile**: Architecture Audit Profile (`architectural`)
- **Scope**: `app/`

## Strengths
- **Clean Route Separation**: Clear separation between Storefront (`app/(store)/`) and Admin (`app/admin/`) boundary layouts.
- **Thin Route Controllers**: Route files (e.g. `app/(store)/index.js`, `app/admin/index.js`) contain minimal presentation logic, delegating state and data fetching to specialized custom hooks (`useCatalogRootData`, `useAppShell`) and domain components.
- **Centralized Provider Shell**: Global context providers are cleanly encapsulated inside `<AppProviders>` in `app/_layout.js` rather than nested haphazardly across child routes.

## Findings

### [FINDING-001]: Deep Relative Directory Traversal Instead of Configured Path Aliases
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `app/_layout.js#L6`, `app/(store)/index.js#L2-L4`, `app/(store)/products/index.js#L2-L4`, `app/(store)/product/[id].js#L3-L6`, `app/(store)/orders.js#L2-L4`, `app/(store)/order-confirmation.js#L2-L5`, `app/(store)/login.js#L2-L3`, `app/(store)/favorites.js#L2-L4`, `app/(store)/contact.js#L2-L4`, `app/(store)/catalog/[categoryId].js#L4-L6`, `app/(store)/catalog/index.js#L2-L4`, `app/(store)/cart.js#L2-L3`, `app/(store)/profile.js#L2-L5`, `app/admin/index.js#L3`
- **Evidence**:
  ```javascript
  // app/(store)/product/[id].js
  import { useTheme } from '../../../src/context/ThemeContext';
  import { useCatalog } from '../../../src/context/CatalogContext';
  import ProductPage from '../../../src/components/ProductPage';
  import PageTransition from '../../../src/components/PageTransition';
  ```
- **Observation**: Route and layout definitions in `app/` bypass the `@/` module path alias configured in the project, relying instead on deeply nested relative paths (`../../` and `../../../`).
- **Impact**: Increases maintenance fragility; moving or restructuring any route file in the folder hierarchy breaks import paths across the routing shell.

### [FINDING-002]: Global Touch Event Wrapping Coupled to Routing Layout Shell
- **Severity**: Low
- **Confidence**: High
- **Affected Scope**: `app/(store)/_layout.js#L22-L25`
- **Evidence**:
  ```javascript
  return (
    <Pressable
      style={[styles.container, ic(isDark, styles.containerDark, styles.containerLight)]}
      onPress={shellData.menuState.closeMenus}
    >
  ```
- **Observation**: The root layout for storefront routes wraps the entire screen structure in a raw React Native `<Pressable>` component to intercept global clicks for menu dismissal.
- **Impact**: Couples transient UI menu state handling directly to the root routing shell; can cause gesture conflicts or touch interception issues with scrolling or interactive child components.
