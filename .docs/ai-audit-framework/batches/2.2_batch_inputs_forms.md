# Stage 2 — Batch Audit Report: Inputs & Form Controls

## Metadata
- **Batch Step ID**: 2.2
- **Profile**: Full UI Audit
- **Scope**: `src/components/**`, `app/**` (Text Inputs, Search Bars, Textareas, Form Wrappers)

## Strengths
- `SharedFormComponents.js` provides `FieldInput` and `FieldTextarea` for Admin entity forms with error state support.
- `SearchBar/SearchInput.js` provides forwardRef support and clear button integration for catalog search.

## Findings

### [FINDING-005]: Direct Raw `TextInput` Usage & Storefront vs Admin Fragmentation
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `src/components/CartSummary.js#L47`, `src/components/Catalog/SidebarUIComponents.js#L32`, `src/features/profile/ProfileFormCard.js#L31`, `src/features/auth/LoginPage.js#L75`
- **Evidence**:
  ```js
  // CartSummary.js
  <TextInput
    value={promoCode}
    onChangeText={setPromoCode}
    placeholder={t('checkout.promoPlaceholder')}
    style={[styles.promoInput, isDark ? styles.promoInputDark : null]}
  />
  ```
- **Observation**: Storefront screens (Cart, Profile, Login, Sidebar filters) bypass shared input primitives and instantiate raw React Native `TextInput` with bespoke styling and manual dark mode logic.
- **Impact**: Fragmented focus rings, non-uniform input heights (38px vs 44px vs 48px), inconsistent placeholder colors, and missing active focus highlight animations.

### [FINDING-006]: Dual Search Input Implementations (`SearchToolbar` vs `SearchInput`)
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/components/SearchToolbar.js#L59-L65`, `src/components/SearchBar/SearchInput.js#L5-L34`
- **Evidence**:
  ```js
  // SearchToolbar.js
  <TextInput
    value={value}
    onChangeText={onChangeText}
    placeholder={placeholder}
    style={textInputStyle}
  />
  // SearchBar/SearchInput.js
  const SearchInput = forwardRef(function SearchInput({ ...props }) { ... })
  ```
- **Observation**: Two competing search input components exist with different clear icon implementations, border radii (8px vs 12px), and icon offsets.
- **Impact**: Disparate search UI experience depending on whether searching from header vs catalog views.

### [FINDING-007]: Non-Standardized Validation & Error State Highlighting
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/components/Admin/SharedFormComponents.js#L8-L20`, `src/components/CartSummary.js#L69`
- **Evidence**:
  ```js
  // Admin FieldInput handles error state:
  error && styles?.fieldInputError
  // Storefront inputs (CartSummary / Contact) have no error prop or visual feedback:
  <TextInput style={styles.input} ... />
  ```
- **Observation**: Form error feedback is non-uniform across the application; admin inputs display red border highlights and sub-text, while storefront inputs rely on toast/alert notifications with no input field highlight.
- **Impact**: Degraded UX during form validation failures on storefront checkout and contact pages.

### [FINDING-008]: Un-unified Textarea Properties & Multi-line Sizing
- **Severity**: Low
- **Confidence**: High
- **Affected Scope**: `src/features/contact/ContactQuestionForm.js#L86`, `src/components/ProductPage/ProductReviewSubcomponents.js#L163`, `src/components/Admin/SharedFormComponents.js#L35`
- **Evidence**:
  ```js
  // ContactQuestionForm uses hardcoded height overrides:
  style={[styles.textarea, ic(styles.textareaDark, styles.textareaLight)]}
  ```
- **Observation**: Multiline text inputs across product reviews, contact forms, and admin modals specify inconsistent heights, line counts, and internal padding.
- **Impact**: Inconsistent textarea presentation across form modal overlays and pages.
