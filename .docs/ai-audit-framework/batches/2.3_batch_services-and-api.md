# Stage 2 — Batch Audit Report: [services-and-api]

## Metadata
- **Batch Step ID**: 2.3
- **Profile**: Architecture Audit Profile (`architectural`)
- **Scope**: `src/services/`

## Strengths
- **Repository Pattern Abstraction**: Data access operations are isolated in `src/services/repositories/`, separating Firestore SDK calls from domain services and UI components.
- **Canonical Response Normalization**: `src/services/serviceContract.js` provides `executeServiceOperation` and `withServiceContract` HOFs to standardize async payload signatures (`{ success, data, error, code }`).
- **Clean Service Adapters**: Domain services like `authService.js` and `telegramService.js` properly apply the service contract wrapper to shield consumers from low-level network or SDK exceptions.

## Findings

### [FINDING-001]: Hardcoded Administrative Credentials in Repository Code
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `src/services/repositories/catalogRepository.js#L9-L11`
- **Evidence**:
  ```javascript
  export async function signInAsAdmin() {
    await signInWithEmailAndPassword(auth, 'admin@pigment-shop.com', 'admin123456');
  }
  ```
- **Observation**: Plaintext administrative login credentials (`admin@pigment-shop.com` / `admin123456`) are committed directly inside client-side repository source code.
- **Impact**: Security vulnerability; exposes administrative access credentials to client-side bundle inspection.

### [FINDING-002]: Inconsistent Service Contract Application Across Data Access Modules
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `src/services/repositories/catalogRepository.js#L30-L70`, `src/services/adminCatalogService.js`
- **Evidence**:
  ```javascript
  // catalogRepository.js throws raw unhandled errors
  try {
    const snapshot = await getCountFromServer(q);
    return snapshot.data().count;
  } catch (error) {
    handleFirestoreQueryError(error, 'product count fetch');
  }
  ```
- **Observation**: Unlike `authService.js` and `telegramService.js`, functions in `catalogRepository.js` and select admin services bypass `withServiceContract` and throw raw error objects directly.
- **Impact**: Forces consuming hooks and UI components to handle mixed response contracts (wrapped `{ success, data }` payloads vs. raw thrown exceptions).
