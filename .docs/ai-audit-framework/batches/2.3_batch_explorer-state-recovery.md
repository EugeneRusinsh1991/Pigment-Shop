# Stage 2 — Batch Audit Report: [explorer-state-recovery]

- **Batch Step ID**: 2.3
- **Profile**: Architecture

## Strengths
- **Graph-Driven Failure Recovery**: `StateRecoveryManager` leverages shortest-path graph traversal (`ExecutionStateGraph`) to navigate back to target states upon UI divergence.
- **SPA Hydration Primitives**: `ReadinessManager` contains specialized DOM polling logic designed to wait for React component mounting rather than raw window load events.
- **Structural DOM Hashing**: `StateCacheManager` calculates DOM structural fingerprints to prevent unnecessary full-page DOM rescans.

## Findings

### [FINDING-009]: Driver Abstraction Leaks via Direct Playwright Imports
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/StateRecoveryManager.ts#L1`, `.tools/browser-automation/explorer/ReadinessManager.ts#L1`
- **Evidence**:
  ```ts
  // StateRecoveryManager.ts
  import { Page, Locator } from 'playwright';

  // ReadinessManager.ts
  import { Page } from 'playwright';
  ```
- **Observation**: `StateRecoveryManager` and `ReadinessManager` bypass driver interface abstractions (`IWebPage`, `IWebElement`) and directly import raw Playwright classes.
- **Impact**: Breaks Dependency Inversion Principle; undermines driver decoupling layer (`driver/DriverInterfaces.ts`), preventing multi-framework browser engine portability.

### [FINDING-010]: Unbounded State Metadata Accumulation & Volatile Single-Cache Strategy
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/StateCacheManager.ts#L19`, `.tools/browser-automation/explorer/StateCacheManager.ts#L48-L56`
- **Evidence**:
  ```ts
  // StateCacheManager.ts
  private currentCache: PageStateCache | null = null;
  ```
- **Observation**: `StateCacheManager` maintains only a single active cache reference while dumping generated DOM state signatures into `ExecutionStateGraph` without cache size bounds or LRU cleanup.
- **Impact**: Memory bloat over extended test runs; loss of cached element references when navigating across deeply nested SPA subroutes.

### [FINDING-011]: Parallel Tracking State Model Duplication
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/NavigationTracker.ts#L2-L3`, `.tools/browser-automation/explorer/ExplorerContext.ts#L8-L10`
- **Evidence**:
  ```ts
  // NavigationTracker.ts
  private visitedScreens = new Set<string>();
  private visitedActions = new Set<string>();

  // ExplorerContext.ts
  visitedScreens: BoundedSet<string>;
  visitedElements: BoundedSet<string>;
  ```
- **Observation**: `NavigationTracker` and `ExplorerContext` separately store duplicate sets tracking visited screens and element actions.
- **Impact**: Single source of truth violation; risk of tracking divergence where elements are recorded as visited in one model but re-processed by another.

### [FINDING-012]: Fragile Magic Selector Heuristics for SPA Page Readiness
- **Severity**: Low
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/ReadinessManager.ts#L13-L18`, `.tools/browser-automation/explorer/ReadinessManager.ts#L23`
- **Evidence**:
  ```ts
  const hasContent = root.querySelectorAll('div, span, p').length > 5;
  await page.waitForTimeout(150);
  ```
- **Observation**: Page readiness relies on hardcoded DOM element threshold counts (`> 5`) and fixed 150ms artificial delays.
- **Impact**: Flaky behavior on lightweight single-element views or custom web component shadow roots.
