## Findings

### [FINDING-005]: Circular Callback Dependency Between Core Exploration Controllers
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/UIExplorer.ts#L64-L70`, `.tools/browser-automation/explorer/InteractionProcessor.ts#L28-L30`, `.tools/browser-automation/explorer/NavigationHandler.ts#L23-L31`
- **Evidence**:
  ```ts
  // UIExplorer.ts constructor callback wiring
  this.interactionProcessor.setNavigationCallback(
    (p, cu, cd, dl, ssId, ti) => this.navHandler.handleNavigationAndRecurse(
      p, cu, cd, dl, ssId, ti,
      (p2, d2, l2) => this.exploreDFS(p2, d2, l2)
    )
  );
  ```
- **Observation**: `UIExplorer`, `InteractionProcessor`, and `NavigationHandler` form a tight triangular circular dependency through manually injected higher-order function callbacks.
- **Impact**: Highly coupled lifecycle; prevents isolated unit testing of navigation processing; risk of unbounded stack depth during complex navigation loops.

### [FINDING-006]: Massive In-Browser Evaluated Script Strings with Manual Polyfills
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/ElementScanner.ts#L15-L42`, `.tools/browser-automation/explorer/ElementScanner.ts#L48-L187`
- **Evidence**:
  ```ts
  // ElementScanner.ts
  const results = await page.evaluate((sel) => {
    // Polyfill for esbuild `__name` helper
    if (typeof globalThis.__name === 'undefined') {
      globalThis.__name = (func: any, name: string) => func;
    }
    // 130+ lines of raw browser JavaScript DOM traversal
  }, selector);
  ```
- **Observation**: 140+ lines of un-typechecked client-side JavaScript are stringified into `page.evaluate()`, including global namespace monkey-patching (`globalThis.__name`).
- **Impact**: Bypasses TypeScript build-time validation; difficult to test browser DOM helpers; risk of pollutive side effects on target web application window context.

### [FINDING-007]: Double DOM Scan & Mismatched Index-Based Locator Resolution
- **Severity**: High
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/ElementScanner.ts#L189-L196`
- **Evidence**:
  ```ts
  const pageLocators = page.locator(selector);
  return results.map(r => ({
    index: r.index,
    identifier: r.identifier,
    locator: pageLocators.nth(r.index),
    metadata: r.metadata as ElementMetadata
  }));
  ```
- **Observation**: Page elements are scanned once via browser `document.querySelectorAll()` and then queried a second time via Playwright's `page.locator().nth(index)`.
- **Impact**: Double scanning penalty on large DOM trees; race conditions causing index mismatches or `StaleElementReference` errors if DOM updates between scans.

### [FINDING-008]: Hardcoded Timeout and Wait Constants Scattered Across Interactors
- **Severity**: Medium
- **Confidence**: High
- **Affected Scope**: `.tools/browser-automation/explorer/NavigationHandler.ts#L36`, `.tools/browser-automation/explorer/ElementInteractor.ts#L15`, `.tools/browser-automation/explorer/ElementInteractor.ts#L59`
- **Evidence**:
  ```ts
  // NavigationHandler.ts
  await page.waitForTimeout(150);

  // ElementInteractor.ts
  await element.click({ timeout: 3000, force: true });
  await element.scrollIntoViewIfNeeded({ timeout: 2000 });
  ```
- **Observation**: Arbitrary magic numbers for timeouts (`150ms`, `3000ms`, `2000ms`) are hardcoded inline instead of centralized in `ExplorerConfig`.
- **Impact**: Prevents environment-specific execution tuning; causes unexpected test flakiness on slower machines or headless CI containers.
