# Руководство по Git и работе с ветками для новичков

## 1. Простая аналогия: Как это работает?

Представьте, что вы пишете важное эссе или книгу на компьютере:
* **Основной документ (`main`)** — это финальная версия вашего файла, которая готова к сдаче или публикации.
* **Ветка (`branch`)** — это черновик (копия файла). Вы копируете документ, чтобы поэкспериментировать с новыми главами или оформлением. Если эксперимент не удался — вы просто удаляете черновик, а оригинальный документ остаётся целым и невредимым.
* **Коммит (`commit`)** — это кнопка «Сохранить» внутри вашего черновика с комментарием («Добавил 2-ю главу»), чтобы в любой момент можно было вернуться к этому моменту.

---

## 2. Наглядный пошаговый процесс (Терминал + Интерфейс IDE)

> 💡 **Как открыть панели управления в IDE:**
> Нажмите **`Ctrl + Shift + G`** (или `Cmd + Shift + G` на Mac) — откроется вкладка **Source Control** (Управление исходным кодом) слева на боковой панели.

---

### Шаг 1: Проверка текущего состояния

* **Через Терминал:**
  ```bash
  git status
  ```
* **Через Интерфейс IDE (`Ctrl + Shift + G`):**
  * **Где смотреть текущую ветку:** В **самом нижнем синем статус-баре слева** (у вас там написано `main*`).
  * **Где смотреть файлы:** В блоке **Changes** вверху боковой панели (список файлов с буквами `M` — изменён, `D` — удалён, `U` — новый).
  * **Где смотреть историю:** В блоке **Graph** ниже списка файлов показано красивое дерево коммитов с овалами веток (`main`).

---

### Шаг 2: Создание черновика (новой ветки)

* **Через Терминал:**
  ```bash
  git checkout -b feature/ui-refactoring
  ```
* **Через Интерфейс IDE (3 простых способа):**
  * **Способ 1 (самый легкий):** Нажмите на слово `main` в **самом нижнем левом углу экрана** (на синей полоске статуса). Вверху всплывет меню — выберите **Create new branch...** (Создать новую ветку).
  * **Способ 2:** В левой панели Source Control вверху нажмите на **три точки `...`** -> **Branch** -> **Create Branch...**.
  * **Способ 3:** Внизу панели в разделе **Graph** нажмите правой кнопкой мыши по самому верхнему синему овалу `main` -> выберите **Create Branch...**.

---

### Шаг 3: Сохранение результатов (Коммит)

Вы переписали код и хотите зафиксировать изменения.

* **Через Терминал:**
  ```bash
  git add .
  git commit -m "feat(ui): изменил цвет и размеры кнопок"
  ```
* **Через Интерфейс IDE (`Ctrl + Shift + G`):**
  1. Наведите на слово **Changes** и нажмите плюс **`+`** (Stage All Changes) — это аналог `git add .`.
  2. В текстовое поле над кнопкой введите комментарий: `"feat(ui): изменил цвет и размеры кнопок"`.
  3. Нажмите синюю кнопку **Commit** (или галочку вверху панели).

---

### Шаг 4: Отправка черновика на GitHub (`git push`)

* **Через Терминал:**
  ```bash
  git push -u origin feature/ui-refactoring
  ```
* **Через Интерфейс IDE:**
  1. После коммита на месте кнопки *Commit* появится синяя кнопка **Publish Branch** (Опубликовать ветку) — нажмите её.
  2. В будущем на этой ветке будет отображаться кнопка **Sync Changes** (Синхронизировать изменения) со стрелочками.

---

### Шаг 5: Что делать дальше? (Финал и Слияние)

#### Вариант А: Изменения отличные, переносим их в `main`

* **Через Терминал:**
  ```bash
  git checkout main
  git merge feature/ui-refactoring
  git push origin main
  ```
* **Через Интерфейс IDE:**
  1. Нажмите на название текущей ветки внизу слева и выберите `main` из списка (переключитесь на `main`).
  2. Нажмите три точки `...` вверху панели Source Control -> **Branch** -> **Merge Branch...**.
  3. Выберите вашу ветку `feature/ui-refactoring`.
  4. Нажмите кнопку **Sync Changes** (Синхронизировать), чтобы отправить обновлённый `main` на GitHub.

#### Вариант Б: Эксперимент не удался, отменяем и удаляем ветку

* **Через Терминал:**
  ```bash
  git checkout main
  git branch -D feature/ui-refactoring
  ```
* **Через Интерфейс IDE:**
  1. Переключитесь обратно на `main` (через нижнюю статус-строку).
  2. Нажмите три точки `...` -> **Branch** -> **Delete Branch...**.
  3. Выберите неудачную ветку для удаления.

## 4. Главные жизненные сценарии (Бэкапы, Откаты, Сохранения)

### Сценарий 1: «Я сделал глупость и хочу все вернуть как было до работы»
Вы написали плохой код в файле и хотите выбросить эти изменения, чтобы вернуть рабочий файл.

* **В интерфейсе IDE (`Ctrl + Shift + G`):**
  * Наведите мышку на изменённый файл в блоке **Changes**.
  * Нажмите на значок **закрученной стрелочки** (стрелочка назад / *Discard Changes*).
  * *Если хотите отменить сразу ВСЕ изменения:* Нажмите на ту же стрелочку назад в заголовке раздела **Changes**.
* **В Терминале:**
  ```bash
  # Сбросить изменения во всех файлах
  git restore .
  ```

---

### Сценарий 2: «Хочу сделать БЭКАП перед опасным экспериментом»
Вы хотите переписать сложную логику, но боитесь всё сломать и хотите безопасную «точку сохранения».

* **В интерфейсе IDE:**
  1. Сделайте коммит ваших текущих рабочих файлов (введите в поле `"backup: перед экспериментом"` и нажмите **Commit**).
  2. Нажмите на ветку в **нижнем левом углу** (`main`) -> **Create new branch...** -> назовите её `experiment-test`.
  3. Теперь вы в полной безопасности! Экспериментируйте. Если не получится — просто переключитесь обратно на `main`.
* **В Терминале:**
  ```bash
  git commit -am "backup: перед экспериментом"
  git checkout -b experiment-test
  ```

---

### Сценарий 3: «Надо срочно переключиться на другую задачу, но код не готов» (Спрятать в карман / Stash)
Вы делаете задачу, и тут просят срочно починить баг на `main`. Коммитить недоделанный код нельзя.

* **В интерфейсе IDE (`Ctrl + Shift + G`):**
  1. Нажмите три точки **`...`** вверху панели Source Control -> **Stash** -> **Stash (Include Untracked)**.
  2. Все ваши незавершённые изменения скроются, и код станет чистым!
  3. Спокойно переключайтесь на `main` и чините баг.
  4. Чтобы вернуть недоделанный код обратно: три точки **`...`** -> **Stash** -> **Pop Latest Stash**.
* **В Терминале:**
  ```bash
  # Спрятать код в "карман" (Stash)
  git stash -u
  
  # Достать код обратно из "кармана"
  git stash pop
  ```

---

### Сценарий 4: «Я сделала коммит, но забыла добавить один файл или ошибся в тексте»

* **В интерфейсе IDE (`Ctrl + Shift + G`):**
  1. Добавьте забытый файл через плюс `+`.
  2. Нажмите на стрелочку рядом с кнопкой *Commit* (или три точки `...` -> **Commit**) -> выберите **Commit (Amend)**.
  3. Старый коммит обновится новым файлом!
* **В Терминале:**
  ```bash
  git add .
  git commit --amend --no-edit
  ```

---

### Сценарий 5: «Я сделал коммит, но понял, что он вообще не нужен (откатить коммит)»

* **В интерфейсе IDE:**
  1. Внизу панели в блоке **Graph** найдите ваш последний коммит.
  2. Нажмите по нему правой кнопкой мыши -> **Reset current branch to this commit...** -> выберите **Soft** (сохранить изменения в файлах) или **Hard** (стереть всё насовсем).
* **В Терминале:**
  ```bash
  # Отменить коммит, но оставить код в файлах для переделки:
  git reset --soft HEAD~1

  # Полностью стереть последний коммит и код из него:
  git reset --hard HEAD~1
  ```

## 5. Частые вопросы про бэкапы и хранение (FAQ)

### ❓ Почему коммит сначала сохраняется ЛОКАЛЬНО?
Git — это **распределённая** система контроля версий.
* Когда вы делаете **Commit**, все изменения сохраняются в базу данных **на вашем компьютере**. Это делается мгновенно и не требует подключения к интернету.
* Вы можете работать в самолёте без интернета, делать десятки коммитов (бэкапов), а когда появится интернет — отправить их все разом на сервер.

---

### ❓ Как отправить локальный бэкап В ОБЛАКО (на GitHub)?
* **В IDE (`Ctrl + Shift + G`):**
  Нажмите синюю кнопку **`Sync Changes 1 ↑`** (или *Publish Branch*, если ветка новая).
* **В Терминале:**
  ```bash
  git push
  ```

---

### ❓ Где физически хранится локальный бэкап?
Все ваши коммиты, история веток и бэкапы хранятся в специальной папке **`.git`** прямо в корне вашего проекта (например: `d:\Magazine\_PigmentShop\.git`).
* **Обратите внимание:** По умолчанию в Windows папка `.git` **скрыта**.
* Заходить в неё вручную и менять файлы **не нужно** — Git сам управляет этой базой данных.
> ⚠️ **Главное правило:** Никогда не удаляйте папку `.git`! Если её удалить — вся история коммитов и бэкапов исчезнет.

### ❓ Как Git хранит всю эту историю и файлы?
Простыми словами, Git работает как **фотоальбом со снимками кода (snapshots)**:

1. **Уникальные хэш-коды (ID):** При каждом коммите Git создаёт слепок всех файлов проекта и даёт ему уникальный код из букв и цифр (например, `src_07-30_00_04`).
2. **Сжатие и оптимизация:** Если из 100 файлов вы изменили только один, Git не будет дублировать оставшиеся 99 файлов. Он просто сохранит ссылку на неизменённые файлы и сжатую разницу (дельту) изменённого файла. 
3. **Дерево коммитов:** Каждый коммит «знает», какой коммит был перед ним. Получается цепочка (как на панели **Graph**). Чтобы отмотать проект назад, Git просто берёт слепок нужной даты и подменяет файлы в вашей рабочей папке на те, что были в тот момент.

---

### ❓ Как «НЕ УДАЛИТЬ» и не потерять свой бэкап?
1. **Делайте коммит перед любыми опасными действиями.** Всё, что закоммичено, очень трудно потерять — Git помнит всю историю.
2. **Всегда нажимайте `Sync Changes` / `git push`.** Если ваш ПК сломается, локальный `.git` погибнет вместе с ним. Облако (GitHub) сохранит ваш код навсегда.
3. **Не используйте команду `git reset --hard` без понимания.** Флаг `--hard` стирает незакоммиченные правки безвозвратно.

## 6. Шпаргалка-сопоставление

| Задача | В Терминале | В IDE (`Ctrl + Shift + G`) |
| :--- | :--- | :--- |
| **Открыть Git** | — | `Ctrl + Shift + G` |
| **Текущая ветка** | `git status` | Смотреть в **самом нижнем левом углу** (синий статус-бар) |
| **График веток** | `git log --graph` | Блок **Graph** внизу панели |
| **Создать ветку** | `git checkout -b имя` | Клик по ветке внизу слева -> *Create new branch* |
| **Подготовить файлы** | `git add .` | Кнопка `+` напротив блока *Changes* |
| **Сделать локальный Бэкап** | `git commit -m "текст"` | Поле ввода вверху + кнопка **Commit** |
| **Отправить бэкап в Облако** | `git push` | Синяя кнопка **Sync Changes 1 ↑** / **Publish Branch** |
| **Переключить ветку** | `git checkout имя` | Клик по ветке внизу слева -> выбрать из списка |
| **Откатить изменения в файле** | `git restore <файл>` | Иконка стрелочки ↩️ напротив файла |
| **Спрятать некоммиченный код** | `git stash` | Три точки `...` -> *Stash* -> *Stash* |
| **Вернуть спрятанный код** | `git stash pop` | Три точки `...` -> *Stash* -> *Pop Stash* |
| **Отменить последний коммит** | `git reset --soft HEAD~1` | Правой кнопкой по коммиту в *Graph* -> *Reset* |
