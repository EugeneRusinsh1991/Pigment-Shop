# 🚀 Universal UI Explorer & Smoke Automation Engine

Документация по архитектуре, функциональным возможностям и перспективам развития автономного движка исследовательского тестирования браузерных приложений.

---

## 📖 1. Обзор архитектуры

Платформа браузерной автоматизации построена на базе **Playwright** и использует события (`ExplorerEventEmitter`) для разделения ответственности:

- **UI Explorer** — чистый навигационный движок. Занимается только обнаружением элементов, переходом по экранам и выполнением действий.
- **Execution Context Architecture** — изолированная подготовка состояния браузера до запуска навигации (например, авторизация под ролями `Guest` или `Admin`).
- **Readiness Manager** — модуль умного ожидания готовности интерфейса.
- **Interaction Policy Engine** — универсальный движок сэмплинга повторяющихся элементов интерфейса.
- **Firestore Diagnostic Analyzer** — парсер и анализатор специфичных ошибок Firestore/Firebase с дедупликацией.
- **Smoke Plugin** — пассивный наблюдатель за здоровьем приложения (Blank screens, React root errors, JS Exceptions, Console Errors).
- **Logger Module** — консольный UI-логгер с ANSI-подсветкой и однострочным представлением действий.

## 🛠 2. Ключевые возможности и функционал

### 🔐 Архитектура Execution Context (Авторизация и роли)
- **Полное разделение ответственности**: Explorer не производит логин сам и не связан с авторизацией.
- **Поддержка профилей**: 
  - `GuestContext` — подготовка сессии гостя.
  - `AdminContext` — автоматический вход в систему до начала обхода (заполнение формы `/login`, ожидание переходного состояния).

### 🔹 Человекоподобная навигация (IDDFS Engine)
- **Отказ от `page.goto()` для внутренних роутов**: навигация происходит исключительно через физические клики пользователем и возврат назад (`page.goBack()`).
- **Алгоритм IDDFS (Iterative Deepening DFS)**: гарантирует сначала полный охват верхнеуровневых разделов (Главная, Каталог, Контакты, Корзина), и только затем погружение вглубь.

### ⚡ Умное ожидание загрузки (Readiness Manager)
- **Исключение сетевых подвисаний**: не блокируется на постоянных WebSockets / Hot Reload (HMR) локального Dev-сервера.
- **Валидация монтирования React DOM**: гарантирует, что Explorer не сканирует пустую HTML-оболочку `<div id="root">`, дожидаясь появления реальных интерактивных элементов.

### 🧠 Сэмплинг повторяющихся элементов (Interaction Policy Engine)
- **Авто-группировка элементов**: объединяет чекбоксы, радиокнопки, списки, сетки товаров и кнопки в логические группы на лету.
- **Равномерное распределение (`Even Distribution`)**: вместо прокликивания 100+ товаров или 50 чекбоксов выбирает репрезентативную выборку (например, 3 чекбокса из 48, 5 товаров из 120), сохраняя высокое покрытие и ускоряя обход в разы.

### 🎯 Семантическое распознавание элементов (Element Scanner)
- Приоритет идентификации: `data-testid` ➔ `aria-label` ➔ Прямой текст ➔ Роль/Тег ➔ Смысловые иконки.
- Полный отказ от вывода анонимного CSS-мусора (`css-view-xxxx`).

### 📊 Система отчётов и диагностики (Smoke Plugin & Firestore Diagnostics)
- **Анализ Firestore**: автоматическая диагностика недостающих композитных индексов (`firestore.indexes.json`) и дедупликация дублирующихся асинхронных предупреждений.
- Категоризация проблем в реальном времени:
  - `[Development Server Issue]` — ошибки загрузки фоновых ресурсов dev-сервера (статусы 400/404 на статичные файлы).
  - `[Application Bug]` — необработанные JS-исключения и упавший код приложения.
  - `[Rendering Issue]` — белый экран или отсутствие компонента `#root`.
- Экспорт результатов в [smoke-report.json](file:///d:/Magazine/_PigmentShop/browser-automation/reports/smoke-report.json).

## 🎨 3. Визуальный CLI-Логгер (Logger Module)

Консольный интерфейс оптимизирован для комфортного наблюдения во время разработки:
- **Однострочный формат успешных действий**:
  - 🟢 `✓ 🔗 Link "Каталог" → /catalog (430 ms)`
  - 🟢 `✓ 🛒 Cart Button (210 ms)`
  - 🔵 `↩ /catalog (85 ms)`
- **Смысловые иконки**: 🏠 `Home`, 🛒 `Cart`, 👤 `Login`, 📂 `Catalog`, 📦 `Product`, ⭐ `Favorite`, ☑ `Checkbox`, 📝 `Input`.
- **Подробные развернутые блоки только при падениях (`❌ FAIL`)**.

## 🔮 4. Потенциальные пути развития (Roadmap)

### 1. Умный ввод данных в формы (Form Fuzzing)
- Подключение генераторов валидных и граничных данных для полей ввода (`Input`) вместо пустых кликов.

### 2. Visual Regression Testing
- Интеграция автоматического снятия скриншотов эталонных экранов при навигации и их сравнение с текущими билдами на предмет вёрстки.

### 3. Интеграция в CI/CD
- Запуск в качестве блокирующего Smoke-степа в GitHub Actions / GitLab CI в headless-режиме с формированием HTML-дашборда отчёта.
